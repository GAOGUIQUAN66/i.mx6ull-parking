## 摘要

针对以上问题，本文设计并实现了一体化的智能车库管理系统，该系统基于 ARM 开发板。本系统围绕“自动化、智能化、可视化”三大目标展开设计，最终实现了六大功能模块。硬件层负责各类外设（USB 摄像头、RFID 读写器、音响、LCD 触摸屏）的物理接入；驱动层基于 Linux 内核适配外设驱动，提供标准化设备接口与通信协议；**应用层基于 Qt 单进程多线程架构实现核心业务逻辑。** 系统以“自动化、智能化、可视化”为核心，实现了六大功能模块：硬件适配与初始化模块完成串口、V4L2 视频子系统、音频子系统的配置；RFID 刷卡认证模块实现卡片感应读取与卡号识别，并联动摄像头抓拍；视频监控与车牌识别模块实现实时视频流显示，并将抓拍图像上传至边侧服务器完成车牌提取；车辆数据管理与计费模块基于 SQLite 数据库自动管理车辆进出信息并计算费用，对非法车辆触发报警；智能语音播报模块通过网络通信将文本发送至边侧合成 WAV 音频并本地播放；用户交互与状态展示模块提供友好的 LCD 触摸屏界面，实时显示系统状态。

## 1.2.3 挑战段（第 51 段）

车库业务管理与调度技术在边缘侧复杂场景下面临着多任务实时协同机制欠缺与资源抢占冲突的挑战。随着系统功能的复杂化，智能车库的运行本质上是一个高频异步的并发过程。视频流的持续采集需要频繁占用 CPU 与内存总线，而 RFID 串口读卡又具有突发性与较高的实时性要求，同时还需兼顾图像上传、SQLite 数据库事务处理及 TCP 网络语音播报。在 ARM Cortex-A 这类计算与内存资源相对有限的平台上，若采用单线程轮询或缺乏合理隔离的调度机制，极易引发多任务间的资源抢占与相互阻塞。这不仅会导致视频画面出现明显卡顿，更可能造成串口数据丢失或识别延迟，从而破坏整个业务流转链路的连贯性。**本系统构建基于 Qt 单进程多线程的并发调度模型，将 RFID 采集、视频预览、数据库访问与网络通信划分至独立工作线程，由主窗口通过信号槽统一编排，将视频处理、串口监听与数据库事务分域调度，有效隔离高负载视频任务对高实时性串口监听的阻塞，提升系统在高并发车流场景下的实时响应能力，从而保障车库复杂调度业务的顺畅流转。**

## 3.2.1 视频识别需求（第 104 段）

在无车辆进出时，**视频采集线程**需基于 V4L2 框架持续获取 USB 摄像头视频流，并在 LCD 屏幕上实时显示监控画面。当**主窗口下发联动抓拍指令**后，系统对截取的原始帧执行水平镜像预处理，并按 RGB565 原始帧或 JPEG/BMP 编码路径封装，**通过 TCP 协议将图像数据发送至局域网内的边侧 Ubuntu 服务器。边侧**调用 HyperLPR3 引擎完成深度学习推理，将识别出的车牌号码、置信度及车牌类型**返回给端侧**，实现云边协同的车牌提取。

**软件需求：** 边缘侧 ARM 节点运行嵌入式 Linux 操作系统，**边侧服务器**运行 Ubuntu Linux；本地数据库采用 SQLite3；**应用层线程间通信基于 Qt 信号槽机制。**

## 4.3.1 线程间通信机制设计（整节替换）

**节标题：** 4.3.1 线程间通信机制设计

**图题：** 图4.3 本地线程间协同机制示意图

**开篇：**

本系统端侧采用 Qt 单进程多线程架构，各业务模块运行于独立工作线程，线程之间通过 Qt 信号槽机制传递事件与业务数据，主窗口统一承担流程调度职能。结合智能车库业务流单向为主、事件触发明确的特点，系统以主窗口为枢纽组织 RFID 采集、视频抓拍、数据库处理与语音播报等环节的协同，其通信关系如图 4.3 所示。

**（1）数据传递：Qt 信号槽机制**

Qt 信号槽是 Qt 框架提供的类型安全异步通信机制。发送方线程发出信号后，接收方对象中的槽函数在各自线程的事件循环中被调度执行，业务代码无需显式轮询共享变量。对于智能车库以事件驱动为主的业务特点，信号槽既能传递 RFID 卡号、识别车牌、播报文本等数据载荷，也能表达抓拍触发、入库完成等时序事件，并保持各模块之间较低的耦合度。

本系统围绕主窗口组织四条核心数据传递链路，承载不同阶段的业务信息：

● RFID 采集线程 → 主窗口：上报有效卡号字符串。RFID 采集线程在串口阻塞读取中解析卡号后，将结果上报主窗口。

● 主窗口 → 视频采集线程：下发抓拍请求。主窗口收到有效卡号后，驱动视频线程截取当前帧并编码上传至边侧服务器。

● 主窗口 → 数据管理模块：传递卡号与识别车牌。主窗口在收到边侧识别结果后，调用 SQLite 接口完成入库、出库或异常校验。

● 主窗口 → 语音播报线程：传递待播报文本。主窗口根据业务结果生成文本，经网络模块请求边侧 TTS 后，由音频播放线程调用 aplay 播放返回的 WAV 文件。上述链路以主窗口为调度枢纽，上游模块完成采集或识别任务并上报结果，由主窗口决定后续环节是否继续执行。

**（2）事件同步：刷卡触发抓拍**

智能车库中 RFID 刷卡与视频抓拍存在严格的先后顺序：必须先确认有效卡号，再截取关联图像。若采用轮询方式持续检查抓拍条件，将浪费 CPU 资源。

本系统在 RFID 采集线程中采用串口阻塞读取，无刷卡时线程挂起等待；当解析出有效卡号后，通过信号上报主窗口，由主窗口向视频采集线程发出抓拍指令。视频线程在未收到请求时仅维持 V4L2 预览采集，不参与业务轮询。该事件驱动方式使 RFID 监听与视频预览并行运行且互不阻塞，有效降低了无效 CPU 占用，提升了 I.MX6ULL 平台在高并发场景下的响应效率。

## 4.3.2 开篇（第 157 段）

语音合成（TTS）任务对算力要求较高，I.MX6ULL 开发板无法本地运行科大讯飞等大型 TTS 引擎，因此需将文本发送至局域网内算力充足的**边侧 Ubuntu 服务器进行合成**，再回传音频数据。针对智慧停车系统中视频流与信令的并发传输需求，合理的组网设计是基础[7]。近年来，基于云边协同架构的智慧停车系统已被证明能有效提升响应效率与资源利用率[22]，本系统的语音合成场景也构成了典型的云边协同通信需求。

## 第 6 章 总结（第 289 段）

随着城市汽车保有量的激增，传统停车场在通行效率与管理模式上的滞后日益凸显。在此背景下，本文设计并实现了一套基于 i.MX6ULL 的智能停车场系统，旨在通过边缘侧的感知与控制提升停车场的自动化水平。系统以嵌入式 Linux 为核心，自底向上打通了硬件驱动、图像采集、核心算法与业务逻辑的完整链路。在硬件端，整合了摄像头、RFID 模块及道闸控制等外设，构建了低功耗的边缘控制节点；在软件端，针对 ARM Cortex-A7 的算力瓶颈，**设计了云边协同机制，将 HyperLPR3 车牌识别与 TTS 语音合成算力卸载至边侧 Ubuntu 服务器；端侧采用 Qt 单进程多线程与事件驱动架构，由主窗口通过信号槽组织 RFID 采集、视频抓拍、数据库处理与语音播报，有效避免了高负载视频任务对串口监听的阻塞。** 同时，结合 SQLite 数据库实现了核心计费数据的本地持久化。经过系统测试，车牌识别与道闸控制的响应延迟控制在合理区间，系统在连续运行下表现出良好的稳定性，验证了该软硬件协同方案的工程可行性。
